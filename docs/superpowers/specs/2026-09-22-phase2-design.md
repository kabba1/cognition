# Phase 2: recoverable cognition

## Authorization and intent

The user supplied their architect's review of the Phase 0–1 baseline and explicitly
instructed continued implementation while they are away. This authorizes Phase 2
and routine design decisions consistent with the academic master specification;
the former separate-packet stop gate no longer blocks work. User input remains
necessary only for a genuine contradictory architectural requirement or unavailable
external credentials. Do not fabricate external architect acceptance.

Build the native synchronous PostgreSQL state machine described by the master:
claim wake, create cycle/turn, compile and persist coherent bounded context,
record invocation start, call interchangeable executive outside a transaction,
persist the exact validated result/decision, apply that decision atomically, then
continue within limits or return to durable sleep. Never resample a stored decision.

## Scope and sequence

First deliver the deterministic Phase 2 execution and recovery gate using the
existing ScriptedModelAdapter. Current focus and self-scheduled wakes are the
initial internal effects. Until the Phase 3 stores exist, other semantic operations
must be explicitly rejected atomically with a durable validation result, never
ignored or represented as applied. Then extend personal state under a separate
Phase 3 design and gate. Existing protocol schemas remain version 1 unchanged.
Live provider adapters, full retrieval/heartbeat policy, perception, external
effects, portability, and UI remain subsequent bounded deliverables.

## Native state machine

- One open cycle per individual, enforced by a partial unique index. Cycle status:
  `active`, `completed`, `failed`; terminal_reason explains wait/sleep/limits/errors.
- A cycle claims a bounded batch of due pending wakes in due-time/UUID order.
  Claim, cycle, wake links, and first turn commit together. Underlying evidence is
  not coalesced. A claimed wake is consumed only when its cycle terminates.
- Turn status: `prepared`, `invoking`, `decided`, `applied`, `rejected`, `failed`.
  Unique (cycle, ordinal), at most one stored decision ID per turn.
- Context and invocation records precede model calls. Context includes its exact
  ModelRequestV1 representation, selected refs, retrieval reasons, hash, config
  revision, runtime contract version, and model adapter/name.
- Model invocation attempts: `started`, `completed`, `failed`, `abandoned`.
  Recovery marks started-without-recorded-result attempts abandoned and may call
  again with the SAME persisted request. Inference can repeat; committed internal
  effects cannot. A stored result/decision is reused, never regenerated.
- Result metadata and exact decision JSON are recorded together. Valid but
  semantically unsupported decisions are preserved before rejection. A mismatched
  request/cycle/turn ID, duplicated operation ID, malformed result, or provider
  failure is recorded as failure without applying proposal contents.
- Turn apply locks affected state, rechecks current lifecycle/governance and
  authority, records operation IDs, applies effects, marks turn applied, and either
  creates the next turn or terminates the cycle/consumes wakes in one transaction.
- `continue` creates a subsequent turn within durable limits. `wait` and `sleep`
  terminate the current cycle; an explicit future wake can resume attention.
- Pause/quiesce/retirement or inference_blocked prevents new inference and state
  application. A result returned after pause is still recorded for honest recovery;
  its application waits for a permitted state. Reconciliation barriers do not grant
  external authority. This slice never dispatches external actions.

## Ownership and transactions

Every execution transaction uses the dedicated RuntimeOwnership.connection. Its
physical loss cannot reconnect, so a former owner cannot commit after a successor
acquires authority. The runtime checks individual identity against ownership.
No SQL transaction is open while ExecutiveModel.decide executes. Context compilation
uses a short REPEATABLE READ transaction and persists its snapshot in that same
transaction. A model result in memory lost on owner death may be regenerated;
a committed decision cannot be regenerated.

Administrative operations retain their own short transactions and may pause or
block the individual while inference is in flight. Do not hold individual or
governance row locks across inference. Runtime exception handling must not
misclassify injected process termination as an ordinary provider failure.

## Schema and interfaces

Add explicit Alembic revision `0004_cognition` after `0003_evidence`, with named
constraints, UUIDs generated by application code, UTC timestamps, and JSONB only
for versioned payloads. Tables/model classes in `db/models/cognition.py`:

- CognitionCycle/cognition_cycles: cycle_id PK, individual_id FK, status,
  started_at, completed_at nullable, terminal_reason nullable, max_turns positive,
  max_attempts_per_turn positive, max_wakes positive, deadline_at, revision>=1.
  Unique individual WHERE status='active'.
- CycleWake/cognition_cycle_wakes: cycle_id FK + wake_id FK composite PK;
  wake_id unique (a wake has one owning cycle).
- CognitionTurn/cognition_turns: turn_id PK, cycle_id FK, ordinal>=1, status,
  created_at, completed_at nullable, decision_id UUID nullable unique,
  decision_json JSONB nullable, decision_hash text nullable, validation_errors
  JSONB list, disposition nullable continue/wait/sleep; unique(cycle_id,ordinal).
- ContextSnapshot/context_snapshots: snapshot_id PK, turn_id unique FK,
  config_revision_id FK, runtime_contract_version, model_adapter, requested_model,
  request_json JSONB, rendered_context text, content_hash text, selected_refs JSONB,
  retrieval_reasons JSONB object, estimated_input_tokens>=0, created_at, retain_until.
- ModelInvocation/model_invocations: invocation_id PK, turn_id FK,
  attempt_number>=1, status, started_at, completed_at nullable, result_json JSONB
  nullable, error_code text nullable; unique(turn_id,attempt_number).
- AppliedOperation/applied_operations: operation_id PK, turn_id FK,
  individual_id FK, kind text, applied_at.
- AttentionState/attention_state: individual_id PK/FK, current_focus JSONB nullable,
  last_cycle_id nullable FK, last_cognition_at nullable, revision>=1.

Frozen execution settings `CycleLimits(max_turns=3,max_attempts_per_turn=2,
max_wakes=16,max_seconds=120,min_wake_delay_seconds=1)` are copied into cycle state;
min_wake_delay_seconds also has a durable column. Recovery uses stored limits.
These are internal deterministic cost caps pending the later complete budget policy.
No unbounded automatic retry or model-driven increase is allowed.

Runtime-facing stores live in `stores/cognition.py`; orchestration lives in
`runtime/cognition.py`. `CognitionRuntime(owner, individual_id, model, clock,
limits=CycleLimits()).run_once()` advances/recover one cycle and returns an
immutable result with cycle ID, status and reason. No sleeps or infinite daemon
loop inside run_once. It returns idle/blocked when no permitted work exists.

## Initial context compiler

`runtime/context.py` exports compile_request using immutable store snapshots:
individual, governance, config, wakes, events, focus, request/cycle/turn IDs and now.
Output CompiledContext holds request, rendered_context, content_hash, selected_refs,
retrieval_reasons, estimated_input_tokens. Pack mandatory control, present/wake,
identity/governance and focus before optional causal/recent evidence. Include
provenance and distinguish evidence from authority. No transcript replay, secrets,
invented hidden experience, or model-produced governance instructions.

Use deterministic UTF-8 byte count as a conservative initial context token estimate
plus fixed framing reserve, explicitly labeled an estimate. Fail before inference
if mandatory content cannot fit; drop optional evidence rather than truncate JSON.
The output schema identifies CognitionDecisionV1; future provider adapters must
account for their actual schema/framing tokens before dispatch. Only exact content
included in the request contributes selected refs. Persist configuration identity
and a stable SHA-256 digest for replay/integrity.

## Evidence, validation and tests

Record cycle start, model decision and terminal/rejection evidence with explicit
runtime/model provenance. No credentials in snapshots or errors. An invocation
failure stores a stable error category, not arbitrary provider exception strings.
Existing fault boundaries are exercised using test-side engine hooks/model callbacks;
production code does not import testing utilities.

Acceptance covers every commit boundary, D1 recorded then crash then D2 forbidden,
D1 unrecorded then retry D2 allowed, context/config frozen across retry, exception
and refusal retry caps, continue/deadline limits, duplicate operation IDs, bad refs,
unsupported operations, pause during model call, ownership loss during model call,
concurrent wake arrival and coalescing, no transaction during inference, immutable
genesis, and clean integrity after recovery. Update Phase 1 tests that asserted no
Phase 2 schema to assert absence of unauthorized external effects instead.

Three alternatives considered: adopting an agent framework would add competing
state ownership; one giant inference transaction violates crash/lock boundaries;
the explicit staged PostgreSQL state machine matches the master and existing code.
