# Phase 4a implementation plan

Start source work only after Phase 3d's full gate is complete and its checkpoint is
published. The user has authorized continued implementation and routine design
choices. Use TDD and the explicit parallel-agent assignments below, followed by
independent review and verification-before-completion. No routine approval gate.

## Shared interface

`domain/attention.py` defines frozen dataclasses:

- `AttentionCandidate(section: ContextSection, reason: str, mandatory: bool=False)`.
- `PersonalAttention(candidates: tuple[AttentionCandidate, ...],
  direct_refs_truncated: int=0, unresolved_direct_refs: int=0,
  linked_refs_truncated: int=0, urgent_scan_truncated: bool=False)`.

Policy constants: version 1, direct ref limit 32, linked ref limit 16, urgent
detail limit 8, urgent horizon 24 hours. Unresolved counts concern supported
personal refs actually attempted; event and other nonpersonal refs are handled
elsewhere and must not be falsely reported as missing personal records.

`stores/attention.py` exposes `build_personal_attention(session, individual_id,
*, wakes, focus, now) -> PersonalAttention`. Candidate reasons are
urgent_commitment, wake_reference, focus_reference, linked_reference and
recent_personal. Candidate primary identity is its first section ref; relationships
may additionally render their owned entity. Roots pass `attention=` into
`compile_request`, mutually exclusive with the legacy `personal_sections=` input.
Legacy calls remain supported. Runtime always uses the new attention builder for
fresh snapshots. This does not recompile already frozen requests.

## Work allocation

1. Root defines shared detached attention records and pure compiler packing/tests.
   Root owns domain/attention.py, runtime/context.py, runtime/cognition.py and
   focused pure context tests. Agree interfaces before dispatch.
2. Store task owns stores/attention.py and rendering refactors needed in personal,
   development and relationship context helpers. Add bounded direct/urgent/linked
   candidate selection and PostgreSQL store tests. Preserve default legacy helpers
   for callers, and keep all personal mutation paths unchanged.
3. Acceptance task adds new tests/acceptance/phase4 coverage after shared interfaces
   exist: fresh-model recall, urgency, tight budgets, foreign refs, frozen replay
   and retrieval without mutation. Own only new acceptance tests.
4. Root integrates runtime candidate construction into the coherent snapshot,
   records omission summaries/reasons, and updates current status/operations docs.
5. Independently review source not authored by the reviewer. Resolve concrete
   findings, run the complete PostgreSQL/Ruff/format/mypy gate with source frozen,
   document accurate results and publish the verified checkpoint. Continue to the
   remaining Phase 4 retrieval/scheduling work afterward.
