# Phase 3 second increment plan

Use executing-plans, test-driven-development, dispatching-parallel-agents for
disjoint tasks, and verification-before-completion. User-authorized autonomous
execution continues after the Phase 3a gate. Spec: ../specs/2026-09-22-phase3b-design.md.

1. Schema task owns db/models/development.py, migration0006_identity_development,
   integration/db/test_development_schema.py. Write real PostgreSQL tests first;
   implement Interest, Preference, SelfState exactly as spec, named constraints,
   nullable pending pairs, unique individual/layer, empty birth, upgrade/downgrade
   and zero metadata drift. Root registers exports and updates schema gate.
2. Store task owns stores/personal.py, new stores/development.py and optional
   stores/personal_core.py, integration/test_development_stores.py and existing
   test_personal_stores.py as needed for preserved behavior. Extract shared change
   plans/locking/snapshot/history helpers if needed to avoid import cycles. Keep
   one whole-decision plan before writes, one exact D1 guard and one apply loop.
   Extend global operation/target checks and reference registry, then plan three
   new families. No separate family applies that could partially commit or treat
   earlier same-decision operations as already-applied collisions. Unit-test
   temporal/evidence rules with FakeClock and real PostgreSQL histories.
3. Root integrates policy family support, frozen-contract compatibility (2.0,
   3.0, 3.1), bounded context instructions, CLI schema gate and integrity checks.
   Preserve current-vs-pending state labels, separated genesis/runtime facts and
   one-object packing. Old committed 3.0 decisions still execute supported families.
4. Acceptance task owns acceptance/phase3/test_development_recovery.py. Test
   first utterance leaves inferred state tentative/pending, reflective promotion,
   passive/retrieval nonpromotion, old-anchor feedback exclusion, restart-preserved
   deadlines, changed pending proposal preserves current content, no genesis edits,
   mixed-family rejection and crash recovery of exact D1 without duplicate effects.
5. Independent review. Fix concrete findings, run full PostgreSQL suite, Ruff,
   formatting and strict mypy; document experimental thresholds and remaining
   relationship/project protocol work, commit and publish the engineering gate.

## Design review

Independent review clarified explicit grounding source/type allowlist, anchor
novelty/union behavior and per-family frozen runtime-contract support. Thresholds
are recorded experimental choices, not claims of empirically established personality.
