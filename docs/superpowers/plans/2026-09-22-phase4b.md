# Phase 4b implementation plan

Begin source work only after Phase 4a's gate is complete and published. Follow the
reviewed lexical design, TDD, explicit parallel tasks below, independent review and
verification-before-completion. User authorization covers this architecture-aligned
increment; no routine approval pause is required.

1. Schema task owns migration0009, expression definitions in db/search.py,
   matching indexes in db/models/personal.py and evidence.py, and dedicated schema
   tests. Three configured bounded expressions only; no canonical text conversion.
   Agree expression helper names before parallel retrieval work.
2. Retrieval task owns stores/lexical.py and its real-PostgreSQL tests. Implement
   deterministic bounded query construction, scoped/filter-before-limit ranked
   retrieval, detached projection rendering and read-only behavior. Do not edit
   the attention compiler or legacy wake/personal mutation paths.
3. Root owns shared domain attention metadata, compiler ordering/summary integration,
   runtime integration, supported schema head, focused pure tests and documentation.
   Preserve executive public schemas and frozen requests.
4. Acceptance task owns new Phase 4 lexical acceptance tests and independent review
   of product files it did not author. Use old records beyond recent pools, a fresh
   model, protected-event exclusions and exact recovery.
5. Resolve review findings before freezing source for the full suite. Record actual
   test/static evidence, commit reviewable pieces and publish a verified checkpoint.
   Heartbeat/reflection/exploration scheduling remains the next bounded increment.
