# Phase 4d implementation plan

Start product work only after the Phase 4c full gate is published. Independently
review the reflection design first. The user's architecture-aligned authorization
covers this increment without a routine approval pause. Use TDD and independent
review before freezing the complete PostgreSQL/static gate.

1. Schema task owns ReflectionState and immutable managed-batch metadata, migration
   0011, model exports and dedicated schema tests. Confirm fields with root first.
2. Selection task owns detached reflection candidate selection and its real-PG
   tests: maturity, owned scope, fixed bounds, per-family cursor wrap and diversity.
   No scheduler mutations or development-validator edits in this task.
3. Scope task owns immutable batch hashing/validation, managed-scope lookup,
   development deliberation/guidance and focused scope tests. Missing managed
   metadata fails closed; generic reflection keeps its independent semantics.
4. Root owns managed reflection scheduling/accounting, runtime/finish integration,
   CLI head, diagnostics and focused integration tests. Preserve previous generic
   reflection behavior and frozen D1.
5. Acceptance task owns bounded fake-clock/fresh-model scenarios and independent
   review of product files it did not author, especially grounding and pause recovery.
6. Resolve review findings, run the complete gate, record actual test evidence and
   publish reviewable commits. Then design explicit bounded internal exploration.

## Agreed internal interfaces

`ReflectionState` uses `interest_cursor`, `preference_cursor`, `self_state_cursor`.
`ManagedReflectionBatch` uses `wake_id`, `individual_id`, `policy_version`,
`target_metadata`, `content_hash`, `selected_at`. Each metadata item has exactly
`kind`, `id`, `revision`, `eligible_at`. Bind all six immutable fields except the
hash itself into canonical sorted compact JSON for SHA-256, using UUID strings and
UTC ISO timestamps. Store order is review order. These are internal contracts.

`stores/reflection_candidates.py` supplies detached `ReflectionCandidate(ref,
revision, eligible_at)`, `earliest_reflection_eligibility(session, individual_id)`
and `select_reflection_candidates(session, individual_id, *, eligible_by, cursors)`.
The fixed limit is eight. Missing cursor keys mean initial position.

`stores/reflection_scope.py` supplies `reflection_batch_hash(...)` with keyword
arguments for the immutable fields and `managed_reflection_scope(session,
individual_id, wake_id) -> tuple[Ref, ...] | None`. None means ordinary reflection;
invalid managed metadata raises an explicit integrity error. Creation markers use
event type `attention.reflection_scheduled`, source kind `runtime`, source ID
`attention.reflection`, and subject kind `wake` with that wake ID. Terminal markers
use `attention.reflection_completed`, the same source and wake subject, and cycle
correlation. Content redaction cannot erase those envelope identities.
