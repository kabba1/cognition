# Phase 4c implementation plan

Start product changes only after Phase 4b's full gate and publication. Independently
review the heartbeat design before implementation. User authorization covers the
architecture-aligned increment; no routine approval pause is needed. Use TDD,
bounded parallel tasks, independent review and verification-before-completion.

1. Schema task owns the new autonomy model/export, migration 0010 and dedicated
   PostgreSQL schema tests. Agree columns with root before parallel product work.
   Preserve durable scheduler continuity on downgrade; no unrelated schema edits.
2. Pure-policy task owns domain/heartbeat.py and pure tests. Implement bounded
   interval transitions and safe deadline calculation without database/runtime
   dependencies. Agree detached API with root; do not edit scheduler stores.
3. Root owns stores/autonomy.py, runtime and cycle-finish integration, CLI schema
   head, diagnostics, focused integration tests and operational documentation.
   Preserve exact-D1 recovery, owner/lifecycle guards and transaction boundaries.
4. Acceptance task owns new heartbeat acceptance cases and independent review of
   product files it did not author. Use FakeClock and fresh scripted models to
   prove backoff, restart continuity, inactivity, reset and exactly-once scheduling.
5. Resolve review findings, freeze source for the full PostgreSQL/static gate,
   record actual evidence and publish reviewable commits. Then continue explicit
   reflection/exploration opportunity design; do not imply a daemon already exists.
