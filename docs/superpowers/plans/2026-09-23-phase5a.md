# Phase 5a implementation plan

Implement only after Phase 4e's frozen full PostgreSQL gate is published. The
reviewed design is [durable inbound perception](../specs/2026-09-22-phase5a-design.md).
User authorization covers architecture-aligned continuation without routine approval
pauses. Use TDD, bounded parallel ownership, independent review and a final source
freeze. Do not connect a live account, acknowledge a provider or invoke a live model.

## Durable schema and shared interfaces

Agree exact columns before parallel implementation. Migration 0013 should add:

- `connector_bindings`: individual-owned immutable adapter and logical source IDs;
  enabled flag; opaque cursor and cursor revision; operational revision; nullable
  pending inbound wake and latest ingestion receipt; creation/update timestamps.
  Unique owner/adapter/source identity. Initial cursor is null at revision zero.
- `inbound_wakes`: wake identity, owner/binding, creation marker and time, nullable
  seal time. A binding has at most one unsealed pending wake. Full or claimed wakes
  are sealed permanently. Generic coalesce key is null.
- `observations`: event primary key, owner/binding, normalized external ID and
  canonical dedup key, fingerprint version/hash, external content type,
  authentication metadata, nullable actual raw-content hash, immutable inbound
  wake membership and ingestion receipt. Unique binding/dedup identity. Event
  content continues to live only in the existing separated ledger tables.
- `ingestion_receipts`: immutable event-backed checkpoint, owner/binding,
  previous checkpoint, before/after cursors and cursor revisions, observed/recorded
  times, source page hash, item/new/duplicate counts and receipt hash. A meaningful
  commit advances cursor revision once even if the opaque cursor value is unchanged.
  The latest checkpoint remains verifiable after event-content redaction; null or
  stale binding cursor/checkpoint pointers cannot make an ingested stream look new.

State revision also changes on source enable/disable and inbound-wake sealing.
It is independent of the cursor revision. Source toggles do not cancel already
recorded observation wakes. Keep checkpoints bounded in size; no duplicate payload
copy belongs in observation or receipt metadata. Guard downgrade against every
populated new table. Add migration/metadata parity and cross-owner store checks.

Receipt continuity is exact: unique `(binding_id, after_cursor_revision)`, nonnegative
before revision and after equal to before plus one. A null predecessor requires
initial revision zero and null initial cursor; otherwise the predecessor's owner,
binding, after cursor and revision equal the next receipt's before values. Count
every repeated page member as a duplicate so `item_count = new_count + duplicate_count`.
Create a receipt only when new observations exist or the cursor changes.

Derive latest checkpoint identity independently from retained ingestion marker
envelopes ordered by event sequence, then require the binding pointer/cursor/revision
to match that receipt. A missing receipt behind a retained marker is an error.
Hash all immutable receipt fields and validate the marker's fixed source, subject,
owner and timestamps without reading redactable EventContent. Full diagnostics
validate the chain and owned observation counts; hot ingestion checks the latest
checkpoint and predecessor without scanning the entire lifetime. A page hash is a
retained commitment, not evidence that redacted payloads can still be reconstructed.

For the binding-to-receipt DDL cycle, use nullable binding pointers and named
`use_alter` FKs, added after tables and removed before downgrade. DML remains ordered:
existing binding, evidence/wakes, receipt, observations, then updated binding
pointers, with explicit flushes inside one transaction. No deferred constraints or
nullable observation receipt membership are needed.

Proposed detached interfaces:

- `ConnectorBindingSnapshot`: binding/owner, adapter/source IDs, cursor and cursor
  revision, binding revision, individual revision and governance revision.
- `normalize_item` and `normalize_page`: pure bounded validation, canonical typed
  identity/fingerprint construction, defensive copies and exact byte accounting.
- `persist_page(session, snapshot, page, recorded_at)`: lock/recheck, validate the
  whole page and all duplicates before writes, append new events/observations,
  append/rotate bounded inbound membership, update cursor/checkpoint atomically.
- `ingest_once(owner, binding_id, connector, clock)`: detached snapshot, adapter
  identity check, fetch outside SQL, normalization outside SQL, ownership fencing,
  short persistence transaction. No provider acknowledgement.
- Inbound scope helpers: classify by records, observation membership, retained
  markers or any binding pointer before filtering mutable wake fields; validate
  exact membership and claimed lifecycle; expose detached discovery to cognition.

## Parallel ownership

1. Schema task owns the new models, exports, migration and PostgreSQL schema tests.
   Coordinate table/FK creation ordering for observation/receipt/wake links.
2. Adapter task owns shared connector records with backwards-compatible fake
   re-exports, pure normalization and the strict bounded `local_json_v1` file source.
   Test count/byte paging, hashes, strict cursors, empty initial streams, malformed
   JSON, duplicate keys, changed fixtures and missing/differing delivery identities.
3. Administrative task owns trusted binding registration/toggle stores, local OS
   authenticated wrapper and connector CLI; exact audit and source epoch changes.
   No generic cursor reset or source rebinding operation. Coordinate the detached
   binding snapshot with root before coding.
4. Root owns atomic page persistence and receipts, bounded connector-owned wake
   membership, ingress runtime and `ingest-once` CLI integration, and cognition
   claim/recovery integration. Treat duplicate-only unchanged pages as no-ops.
   Preflight the whole page before appending evidence. Serialize with the same
   individual/governance/binding lock order as administration.
5. As slots free, assign independent diagnostics and acceptance tasks. Diagnostics
   must use Core/no-autoflush snapshots and cover all historical membership and
   checkpoint chains. Acceptance uses fresh connectors/models and FakeClock,
   corruption/fault injection, concurrency, source disable/pause during fetch,
   ownership loss, duplicate/redacted replay and prompt injection claims.

Before generic orphan recovery, reject orphan managed inbound claims. For fresh
claims, an earliest inbound wake runs alone; an earliest ordinary wake may start
an ordinary-only bounded batch. Preserve due times and document limited overtaking.
Exploration remains lower priority than all ordinary due work. Existing active
cycles and public executive contracts retain their original behavior.

## Gate and handoff

Resolve design/implementation review findings with regression evidence. Run static
checks and targeted old-runtime/attention/admin regressions, then freeze source for
the complete PostgreSQL suite. Record actual results and limitations, update the
operator/handoff documents and publish reviewed commits to the existing repository.
Continue with entity identifier binding and other perception gaps after this gate;
do not describe the fixture adapter as a live inbox or a complete perception system.
