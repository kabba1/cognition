# Explicit executive extension implementation plan

Apply the reviewed Phase 3d design after the Phase 3c gate. Preserve v1 classes,
goldens and committed JSON exactly. User authorization covers filling these
architectural gaps; engineering gates are checkpoints, not requests to stop.
Use TDD, dispatching-parallel-agents for the disjoint tasks below, independent
review and verification-before-completion. Do not edit source during Phase 3c's
full-suite checkpoint run.

## Interfaces agreed before parallel work

- protocols/common.py adds strict VersionTwo without changing VersionOne.
- protocols/cognition_v2.py defines EntityOperation, ProjectOperation,
  RelationshipOperation, RelationshipThreadOperation, CognitionDecisionV2.
- protocols/model_v2.py defines ModelRequestV2 and ModelResultV2, reusing unchanged
  ContextSection, TokenUsage and ModelError from v1.
- protocols/executive.py exposes type aliases CognitionDecision, ModelRequest,
  ModelResult and parse_decision/parse_request/parse_result strict dispatch helpers.
  It also validates allowed request/output-schema/runtime-contract tuples and
  configuration selection using explicit scalar inputs, avoiding config imports.
- config/schema.py preserves ConfigV1 and BehaviorConfig, adds ConfigV2 and
  BehaviorConfigV2, plus Configuration/BehaviorConfiguration union aliases and
  strict parsing helpers. V2 has execution.cognition_protocol_version=2.

## Disjoint implementation tasks

1. Protocol task owns common.py, the three new protocol modules, new contract
   fixtures/goldens/tests and compatibility registry updates. No edits to v1
   schema-bearing models. Compare existing v1 goldens byte/schema-equivalently.
   Test required arrays, strict versions, malformed operations and tuple rejection.
2. Configuration task owns config/*, stores/configuration.py, db/models/runtime.py,
   migration0008_executive_configuration.py and new configuration/migration tests.
   Preserve v1 serialized behavior and hashes; authenticate/config-evidence path
   remains. Widen DB version constraint; refuse downgrade if v2 history exists.
   Root adjusts birth type annotation, supported schema gate and diagnostics.
3. Personal extension task owns stores/executive_personal.py, personal.py,
   development.py type annotations, policy/cognition.py and focused new store/policy
   tests. Plan new families without writes, then join the existing shared atomic
   apply loop. Keep all eleven families under one exact D1 guard, global ID/target
   validation, owned-reference rules and limits. Reuse v1 transition behavior.
4. Root owns runtime/context.py, runtime/cognition.py, stores/cognition.py,
   models/base.py, models/script_file.py, testing/scripted_model.py, CLI run and
   schema gate, db/checks.py, birth type integration and runtime/CLI tests. Freeze
   version/config at snapshot commit; validate request/config/contract/result tuples
   and denormalized snapshot linkage at load/apply/check. Preserve supported frozen
   v1 contracts. Add adapter-free committed recovery before fresh-inference checks.

## Final integration

Add v2 end-to-end decision/recovery acceptance: deliberate entity/project creation,
later-turn relationship/thread creation, no authority from social claims, mixed
family rejection, exact retained v1/v2 replay after interruption, config changes
around snapshot freeze, incompatible request/result/version handling, recovery-only
CLI and continued-cycle blocking when an adapter is unavailable. Independently
review cross-file version handling and atomicity, fix findings, then run complete
PostgreSQL/static gates and publish the next verified checkpoint.
